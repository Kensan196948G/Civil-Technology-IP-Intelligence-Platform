## 4. 共通UIコンポーネント

| コンポーネント | 用途 | 制約 |
|---|---|---|
| `<EvidenceLink>` | 根拠原文へのリンク | 出典・該当箇所・取得日時を必ず表示 |
| `<AiOutput>` | AI出力の表示枠 | 「判断ではない」旨の注記を内蔵。prop で消せない |
| `<ClaimSimilarity>` | 類似度の表示 | 注記を内蔵。数値のみの表示を禁止 |
| `<FieldScore>` | 現場適用性スコア | 軸別内訳を必ず併記。スコア単独表示を禁止 |
| `<ClassificationBadge>` | 機密区分の表示 | C1〜C4 を色と文字で示す |
| `<JobStatus>` | 非同期ジョブの進捗 | 状態・進捗・推定残り時間・失敗時の再実行 |
| `<ApprovalPanel>` | 承認操作 | 自己承認時は操作不可。理由入力を必須化 |
| `<ExportButton>` | エクスポート | 権限がなければ非表示。透かし付与を明示 |

```tsx
// 注記の除去を防ぐ設計例
export function ClaimSimilarity({ value }: { value: number }) {
  return (
    <div>
      <strong>{(value * 100).toFixed(0)}%</strong>
      <p role="note">類似度は権利侵害の判断ではありません。専門家の確認が必要です。</p>
    </div>
  )
}
// 注記を prop で受け取らない = 呼び出し側から消せない
```

## 5. 主要画面の設計要点

### S-02 / S-03 横断検索

| 要素 | 設計 |
|---|---|
| 入力 | 単一の検索窓。自然文と語句の両方を受け付ける |
| 検索式 | AI生成の検索式を**表示し、編集可能にする**。ブラックボックスにしない |
| 結果 | 種別タブ（特許／論文／NETIS／技術／過去調査）と件数 |
| 各件 | タイトル、抜粋（一致箇所ハイライト）、出典、取得日時、機密区分 |
| スコア | 内訳（字句順位・意味順位）を折りたたみで開示 |
| 0件時 | 条件緩和の候補を提示（同義語、期間拡大、分類の上位化） |
| 保存 | 検索条件を保存し、後日再実行・差分確認できる |

### S-08 特許詳細

```text
┌ 書誌（番号・出願人・日付・法的状態） ────────────┐
├ タブ: 請求項 / 明細 / ファミリー / 引用 / 関連 / 社内評価 ┤
│ 請求項タブ                                        │
│   Claim Tree（独立・従属の階層）                   │
│   [請求項を読み解く] → 構成要件分解 + 平易な日本語   │
│   各出力に <EvidenceLink> で原文の該当箇所へ        │
└──────────────────────────────────────────────┘
```

### S-13 Claim Chart

```text
┌ 注記バー（常時表示・閉じられない） ──────────────┐
│ 類似度は権利侵害の判断ではありません                │
├───────────┬──────────┬──────────┬───────────┤
│ 構成要件   │ 他社特許  │ 自社案    │ 判定       │
├───────────┼──────────┼──────────┼───────────┤
│ A          │ 原文抜粋  │ 該当あり  │ 一致 [編集] │
│ B          │ 原文抜粋  │ 一部相違  │ 類似 [編集] │
│ C          │ 原文抜粋  │ 見あたらず│ 相違 [編集] │
└───────────┴──────────┴──────────┴───────────┘
   各行に根拠リンク。判定は人が修正でき、履歴が残る
```

### S-18 現場課題の登録（スマートフォン前提）

| 設計方針 | 内容 |
|---|---|
| 必須項目 | 現場・課題本文のみ。他はすべて任意 |
| 入力 | 自然文で書けばよい。分類・整形はAIが行い、後から確認できる |
| 写真 | カメラから直接添付。R2 へ直接アップロード（署名付きURL） |
| オフライン | 下書きをローカル保存し、接続時に送信 |
| 所要時間 | 1分以内で送信完了できることを設計目標とする |

### S-29 承認・案件一覧

| 要素 | 設計 |
|---|---|
| 既定表示 | 自分が承認者の案件 → 自分が担当の案件 → 差戻し中 |
| 各件 | 種別、件名、現ステータス、期限、前ステップの結果 |
| 承認操作 | 承認 / 差戻し / 保留。差戻しは理由必須 |
| 自己承認 | 起案者本人には操作ボタンを表示しない |
| AI直後 | AIステップの結果と「人間確認事項」を必ず表示してから承認させる |

## 6. アクセシビリティ・表示要件

| 項目 | 要件 |
|---|---|
| 目標 | WCAG 2.1 AA |
| キーボード | 主要操作をキーボードのみで完了できる |
| フォーカス | 可視のフォーカスリングを持つ |
| コントラスト | 本文 4.5:1 以上 |
| 色 | 色のみで意味を伝えない（判定は文字も併記） |
| 文字サイズ | ブラウザのズームに追従する |
| 動き | `prefers-reduced-motion` を尊重する |
| テーマ | ライト／ダークの両方に対応する |

## 7. 表示上の禁止事項

| # | 禁止 |
|---|---|
| 1 | AI出力を注記なしで表示すること |
| 2 | 類似度を数値のみで表示すること |
| 3 | スコアを軸別内訳なしで表示すること |
| 4 | 権限のないモジュールをグレーアウトで表示すること（存在を示さない） |
| 5 | 非同期処理の進捗を示さずに待たせること |
| 6 | エラーの原因と次の操作を示さないこと |
