# ADR-0002 TypeScript モノレポ（pnpm + Turborepo）で構成する

| 項目 | 値 |
|---|---|
| 状態 | 採択 |
| 日付 | 2026-08-22 |

## 文脈

Web（Next.js）、API（Hono）、複数の Worker、共有ロジック（検索・AI・権限・スキーマ）が必要になる。
特に **DBスキーマの型** と **API入出力の型** を全体で共有しないと、境界での不整合が頻発する。

## 決定

pnpm workspaces + Turborepo による TypeScript モノレポとする。

```text
apps/web, apps/api, workers/*, packages/{db,core,ai,search,ui,config}
```

## 理由

- Drizzle のスキーマ型を `packages/db` から全アプリへ供給できる
- Zod スキーマを API と画面で共有し、境界の不整合をコンパイル時に検出できる
- 権限判定・スコア算出などのドメインロジックを `packages/core` に一箇所で持てる
- Turborepo のキャッシュにより、CI でのビルド時間を抑えられる

## 結果

**良い点**: 型の一貫性、ロジックの重複排除、変更の影響範囲が追跡しやすい
**悪い点**: 初期構築の手間、依存の循環に注意が必要、ビルド設定が複雑になりやすい

## 代替案

| 案 | 不採用の理由 |
|---|---|
| リポジトリ分割 | 型共有ができず、境界の不整合が増える。同時変更のPRが分散する |
| npm workspaces のみ | 大規模化時のインストール速度とキャッシュで劣る |

## 再評価条件

- ビルド時間が許容範囲を超えた場合
- チームが分割され、リポジトリ単位の権限分離が必要になった場合
