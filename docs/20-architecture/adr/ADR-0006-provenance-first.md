# ADR-0006 Provenance をデータモデルの中核に置く

| 項目 | 値 |
|---|---|
| 状態 | 採択 |
| 日付 | 2026-08-22 |
| 重要度 | **高**。設計上の絶対条件に対応する |

## 文脈

本システムの設計上の絶対条件に「AIは決定しない」「根拠を必ず残す」がある。
AI が出した内容を人が判断するには、その根拠を原文まで遡れなければならない。

```text
AI回答 → 根拠 → 特許番号 → Claim → 該当文 → 取得元 → 取得日時
```

Provenance を後付けで導入することはできない。既存のAI出力に根拠を遡って付けることは不可能であり、
「根拠のある出力」と「ない出力」が混在すれば、原則そのものが形骸化する。

## 決定

- `ai_runs`（AI実行）と `ai_citations`（根拠）を**最初のマイグレーションから**中核テーブルとして定義する
- **`ai_citations` が0件の `ai_runs` は `status = invalid`** とし、確定成果物として扱わない
- 取り込む全レコードに `source` / `source_url` / `retrieved_at` / `license_note` を必須列として持たせる
- 引用は「文献ID」だけでなく **locator（請求項番号・段落・文字オフセット）と quoted_text（該当文）** まで保持する
- 画面は根拠へ **2クリック以内**（NFR-U-004）で到達できること

## 理由

- 「AIは決めない」を担保する唯一の手段が、判断材料としての根拠の提示である
- 外部データの再配布制限に対応するには、出典と取得日時の保持が必須である
- 監査・調査記録（FR-M05-004）の要件と同じ基盤で満たせる
- 後付けが不可能な性質の要件であるため、初期から強制する

## 結果

**良い点**

- AI出力の信頼性を利用者が自分で検証できる
- 監査・外部説明に耐える
- モデル差し替え時、過去結果の再現可能性を判断できる（`model` / `prompt_version` を記録）

**悪い点 / 受け入れるコスト**

- 実装コストが上がる。すべてのAI処理で引用抽出が必要になる
- ストレージが増える（quoted_text の保持）
- 引用の抽出精度が低いと、根拠が不正確になる。**引用は生成させず、検索で取得した原文の該当箇所を機械的に紐づける**

## 実装上の必須ルール

1. 引用文（`quoted_text`）は **AI に生成させず**、検索で取得した原文から機械的に切り出す
2. `ai_runs` には `model`, `prompt_version`, `params`, `input_hash`, `token_usage` を必ず記録する
3. CI に「`ai_citations` を作らない AI 実行パス」を検出するテストを置く
4. 受入条件 A-03（充足率100%）を DB クエリで継続検証する

## 代替案

| 案 | 不採用の理由 |
|---|---|
| 根拠を任意項目とする | 原則が形骸化する。混在した時点で信頼性の担保ができない |
| 引用文もAIに生成させる | 存在しない文を引用する危険がある（最も避けるべき失敗） |
| 文献IDのみ保持し、該当箇所は保持しない | 「2クリックで根拠へ」を満たせず、確認コストが高くて使われなくなる |

## 再評価条件

なし。本決定は設計上の絶対条件に対応するものであり、緩和しない。
実装方式（引用の切り出し手法）は改善しうるが、Provenance の必須性は変更しない。
