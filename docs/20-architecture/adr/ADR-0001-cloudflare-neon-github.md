# ADR-0001 実行基盤を Cloudflare、DBを Neon、CI/CD を GitHub Actions とする

| 項目 | 値 |
|---|---|
| 状態 | 採択 |
| 日付 | 2026-08-22 |

## 文脈

利用サービスとして GitHub / Cloudflare / Neon が指定されている。
ドメイン `mirai-dx-platform.com` は取得済みで、サブドメイン `ctiip` を新規に割り当てる。
社内システムであり、常時高負荷ではないが、特許データの取り込みなど断続的に重い処理が発生する。

## 決定

- Web / API / 非同期処理をすべて **Cloudflare Workers** 上で動かす
- 主データベースは **Neon PostgreSQL**（pgvector / pg_trgm 拡張を使用）
- ソース管理と CI/CD は **GitHub / GitHub Actions**
- オブジェクトは **Cloudflare R2**、キューは **Cloudflare Queues**、多段実行は **Cloudflare Workflows**
- 認証は **Cloudflare Access**

## 理由

| 観点 | 内容 |
|---|---|
| 指定要件 | 3サービスの利用が前提として与えられている |
| コスト | 常時稼働のコンテナを持たない。断続的な負荷に適する |
| 運用負荷 | サーバ・OS・パッチ管理が不要。小規模チームで運用できる |
| 一貫性 | 認証・配信・実行・ストレージ・キューが同一プラットフォームで完結し、境界が減る |
| DB | Neon のブランチ機能により、PR ごとに独立した検証用DBを作れる |
| ベクトル | pgvector により、業務データと同一トランザクション・同一権限で意味検索を扱える |

## 結果

**良い点**

- インフラ運用の対象が最小になる
- PR ごとの完全な検証環境（Worker preview + Neon branch）が安価に作れる
- ベクトルと業務データが同居するため、権限制御が一箇所で済む

**悪い点 / 受け入れるリスク**

- Worker の実行時間・メモリ制約により、長時間処理を分割する設計が必須になる（→ ADR-0004）
- Neon に日本語形態素解析拡張が無く、全文検索の設計に制約が出る（→ ADR-0003）
- Cloudflare / Neon への依存が高い。移行は容易でない
- エッジ実行とDBリージョンの距離がレイテンシに影響する。リージョン固定が必要

## 代替案

| 案 | 不採用の理由 |
|---|---|
| コンテナ基盤（ECS / Cloud Run 等）+ RDS | 指定サービス外。常時コストと運用負荷が増える |
| Cloudflare + 外部ベクトルDB | データが二重管理になり、C3/C4 の権限制御が複雑化する |
| 全文検索専用エンジンの併設 | Phase 1 では運用対象を増やしたくない（ADR-0003 で再評価） |

## 再評価条件

- 検索品質が業務上許容できない水準と判断された場合（ADR-0003 の再評価と連動）
- 特許データ量が想定を大きく超え、Neon の性能・コストが問題化した場合
- Worker の制約により実装が著しく困難な機能が発生した場合
