# ⚙️ 非機能要件

ID 体系: `NFR-<区分>-<連番>`
区分: `P`=性能 / `A`=可用性 / `S`=セキュリティ / `O`=運用 / `C`=互換 / `U`=ユーザビリティ / `X`=拡張性 / `L`=法令・監査

⚠️ 数値目標のうち「**要決定**」は Phase 0〜1 の実測とサービスレベル合意により確定する。根拠のない数値を先に置かない。

---

## P 性能

| ID | 要件 | 目標 | 測定方法 |
|---|---|---|---|
| NFR-P-001 | 画面初期表示（ダッシュボード） | ⚠️ 要決定（暫定 p95 ≤ 2.0s） | 合成監視 |
| NFR-P-002 | 横断検索の応答（1万件規模の結果集合） | ⚠️ 要決定（暫定 p95 ≤ 2.0s） | 負荷試験 |
| NFR-P-003 | ベクトル検索（上位50件） | 暫定 p95 ≤ 800ms | 負荷試験 |
| NFR-P-004 | Claim 分解（1特許） | 非同期。暫定 ≤ 60s | ジョブ実測 |
| NFR-P-005 | AI模擬審査（1発明・先行文献10件） | 非同期。暫定 ≤ 5分 | ジョブ実測 |
| NFR-P-006 | 自律エージェント連続実行（M21） | 非同期。暫定 ≤ 30分 | ジョブ実測 |
| NFR-P-007 | 帳票生成（PDF・50ページ） | 非同期。暫定 ≤ 60s | ジョブ実測 |
| NFR-P-008 | 同時利用者数 | ⚠️ 要決定（利用者数確定後） | 負荷試験 |
| NFR-P-009 | 特許データ取り込み | 日次バッチが業務時間外に完了すること | バッチ実測 |

**設計方針**: 60秒を超える可能性のある処理はすべて非同期（202 Accepted + ジョブID）とする。同期APIで実装しない。

| ID | 要件 | 目標 |
|---|---|---|
| NFR-A-001 | 稼働率（営業時間帯 平日 8:00-20:00 JST） | ⚠️ 要決定（暫定 99.5%） |
| NFR-A-002 | 計画停止 | 事前告知のうえ業務時間外に実施 |
| NFR-A-003 | RPO（目標復旧時点） | ⚠️ 要決定（暫定 15分。Neon PITR に依拠） |
| NFR-A-004 | RTO（目標復旧時間） | ⚠️ 要決定（暫定 4時間） |

## S セキュリティ

| ID | 要件 | 優先度 |
|---|---|---|
| NFR-S-001 | 認証は SSO（Cloudflare Access + IdP）とし、MFA を必須とする | MUST |
| NFR-S-002 | すべての通信を TLS 1.2 以上で暗号化する | MUST |
| NFR-S-003 | 保存データを暗号化する（Neon／R2 の保存時暗号化） | MUST |
| NFR-S-004 | RBAC に加え、プロジェクト単位の行レベル制御を行う | MUST |
| NFR-S-005 | データ分類 C3 以上のレコードは、参加者以外に一覧・検索結果にも出現させない | MUST |
| NFR-S-006 | エクスポート・ダウンロードは権限で制御し、全件を監査ログに記録する | MUST |
| NFR-S-007 | AIプロバイダへ送信するデータの範囲をポリシーで制御し、C4 は既定で送信しない | MUST |
| NFR-S-008 | APIは認証必須。Rate Limit（利用者単位・IP単位）を設ける | MUST |
| NFR-S-009 | シークレットをリポジトリへ含めない。CI/CDで秘密検出を実行する | MUST |
| NFR-S-010 | 依存パッケージの脆弱性を継続監視し、critical / high をゼロに保つ | MUST |
| NFR-S-011 | 管理者権限の操作は追加確認（再認証）を要求する | SHOULD |
| NFR-S-012 | セッションのアイドルタイムアウトを設ける | MUST（⚠️ 時間は要決定） |

## O 運用

| ID | 要件 | 目標 |
|---|---|---|
| NFR-O-001 | バックアップ | Neon PITR ＋ 日次論理バックアップを R2 へ保管 |
| NFR-O-002 | 復旧手順 | 手順書化し、半期ごとに復旧訓練を実施する |
| NFR-O-003 | 監視 | 可用性・エラー率・応答時間・ジョブ滞留・コストを監視する |
| NFR-O-004 | アラート | 閾値超過を担当者へ通知する（宛先は ⚠️ 要決定） |
| NFR-O-005 | ログ保持 | アプリログ 90日、監査ログ ⚠️ 要決定（法定・社内規程と整合） |
| NFR-O-006 | デプロイ | 無停止デプロイ。ロールバック手順を用意する |
| NFR-O-007 | コスト監視 | AI利用量・DB容量・帯域を月次で可視化する |
| NFR-O-008 | データ品質監視 | 欠損率・重複率・分類付与率を週次で計測する |

## C 互換性

| ID | 要件 |
|---|---|
| NFR-C-001 | 対応ブラウザ：Chrome / Edge / Safari の各現行版および1つ前のメジャー版 |
| NFR-C-002 | 画面はレスポンシブ対応。現場利用を想定しスマートフォン幅で操作可能とする |
| NFR-C-003 | 帳票出力は指定の6形式（HTML / PDF / DOCX / XLSX / CSV / JSON）を満たす |
| NFR-C-004 | 文字コードは UTF-8。CSV 出力は Excel 互換（BOM付き）を選択可能とする |
| NFR-C-005 | 日本語（常用漢字・旧字・機種依存文字）を扱えること。特許文献特有の記号を欠落させないこと |

## U ユーザビリティ

| ID | 要件 |
|---|---|
| NFR-U-001 | UI表記は日本語。専門用語には用語集へのリンクを設ける |
| NFR-U-002 | 現場からの入力は必須項目を最小化し、自然文入力を許容する |
| NFR-U-003 | AI出力には「判断ではない」旨の注記を常時表示し、非表示にできない |
| NFR-U-004 | 検索結果・分析結果から、根拠原文へ2クリック以内で到達できる |
| NFR-U-005 | 処理待ちの操作には進捗と推定残り時間を表示する |
| NFR-U-006 | キーボード操作と画面読み上げに配慮する（WCAG 2.1 AA を目標） |
| NFR-U-007 | エラーメッセージは原因と次の操作を日本語で示す |

## X 拡張性

| ID | 要件 |
|---|---|
| NFR-X-001 | 特許100万件・論文50万件・チャンク1,000万件の規模で設計する（⚠️ 実数は要決定） |
| NFR-X-002 | 新しい外部データ源を、取り込みアダプタの追加のみで接続できる構造とする |
| NFR-X-003 | 埋め込みモデル・言語モデルを差し替え可能とし、モデルIDをデータに記録する |
| NFR-X-004 | 分類体系（工種・技術分類）をマスタとして追加・改訂できる |
| NFR-X-005 | モジュール単位で有効／無効を切り替えられる（フェーズ導入のため） |

## L 法令・監査

| ID | 要件 |
|---|---|
| NFR-L-001 | 監査ログは改変不可（追記専用）とし、削除操作を残す |
| NFR-L-002 | 個人情報（発明者名・研究者名等）の取扱いを規程に沿って行う |
| NFR-L-003 | 外部データの再配布制限を守る。エクスポートに出典表記を強制する |
| NFR-L-004 | 社外に対する鑑定・法的判断の提供を行わない旨をシステム上で担保する |
| NFR-L-005 | 職務発明規程との整合（発明者記録、報奨判定に必要な情報の保持） |
| NFR-L-006 | データ保持期間とアーカイブ方針を設定できる（⚠️ 期間は要決定） |

## 制約に基づく設計上の帰結

| 制約 | 帰結 |
|---|---|
| Workers の1リクエストCPU時間上限 | 重い処理は Queues / Workflows へ。API は非同期契約 |
| Neon に日本語形態素解析拡張なし | pg_trgm + pgvector のハイブリッド検索（[ADR-0003](../20-architecture/adr/ADR-0003-japanese-search.md)） |
| サーバーレスDBの接続数 | 接続プーリング（Neon Pooler）を使用し、コネクションを保持しない |
| エッジ実行の地理分散 | DBリージョンを固定し、レイテンシを考慮した配置とする（⚠️ リージョン要決定） |
