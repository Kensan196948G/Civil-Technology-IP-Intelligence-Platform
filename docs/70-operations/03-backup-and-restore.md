## 3. 論理バックアップ

```bash
# 日次 23:00 JST（Cron Worker から起動、または外部ジョブ）
pg_dump "$DATABASE_URL_DIRECT" \
  --format=custom --no-owner --no-privileges \
  | gzip > dump.sql.gz
# → R2: backup/{yyyy-mm-dd}/dump.sql.gz へ保存（暗号化）
```

| 項目 | 方針 |
|---|---|
| 保持 | ⚠️ 要決定（監査要件と整合。暫定 日次30世代 + 月次12世代） |
| 暗号化 | 保存時暗号化。アクセス権を限定 |
| 検証 | 週次で1件を実際にリストアして検証する（取れているだけでは不十分） |

## 4. 復旧手順

### 4.1 誤操作によるデータ消失（一部）

```text
① 影響範囲を特定（audit_logs で操作を追跡）
② Neon PITR で該当時点のブランチを作成
③ 復旧用ブランチから対象データを抽出
④ 本番へ復元（差分のみ）
⑤ 監査ログに復旧操作を記録
```

**MUST**: 本番全体を巻き戻す前に、差分復旧で足りないか検討する。

### 4.2 DB 全体の破損

```text
① 🔒 承認を得る（本番データに影響する）
② 直近の健全な時点を特定
③ Neon PITR でその時点へ復旧、または論理バックアップからリストア
④ アプリを停止して整合性を確認
⑤ 復旧後のデータ検証（件数・整合性チェック）
⑥ アプリを再開
⑦ 失われた期間の再取り込み（外部データは再取得可能）
⑧ 報告
```

### 4.3 R2 オブジェクトの消失

| 対象 | 復旧方法 |
|---|---|
| `raw/` | 外部データ源から再取得 |
| `docs/`（原文PDF） | 外部データ源から再取得。**社内添付（発明届の図面等）は再取得不能** ⚠️ 複製方針の決定が必要 |
| `reports/` | 再生成 |
| `backup/` | 復旧不能。多重化を検討 |

⚠️ **要決定** — 社内添付ファイルの複製方針。再取得できないデータであるため、
Phase 1 で方針を決める（別バケット複製 / 別リージョン / 定期エクスポート）。
