# 📝 テスト仕様

## 1. 権限テスト（最重点）

### 1.1 機密区分の遮蔽

| # | 条件 | 期待 |
|---|---|---|
| A-1 | C3 の発明を、非参加者が ID 指定で取得 | **404**（403 ではない） |
| A-2 | C3 の発明を含む条件で、非参加者が検索 | 結果に含まれない。**総件数にも含まれない** |
| A-3 | C3 の発明を含む条件で、非参加者がファセット集計 | 件数に含まれない |
| A-4 | C4 の情報を、個別付与のない技術管理者が取得 | 404 |
| A-5 | C4 の情報を、個別付与のある利用者が取得 | 200 |
| A-6 | 付与の期限切れ後に C4 を取得 | 404 |
| A-7 | C3 のチャンクが RAG の根拠に使われるか（非参加者の質問） | 使われない |

**検証方法**: API レベル（結合テスト）と SQL レベル（クエリに権限条件が含まれること）の両方で確認する。

### 1.2 ロール別の機能権限

権限マトリクス（[../10-requirements/05-rbac-matrix.md](../10-requirements/05-rbac-matrix.md)）の
**全セルについて**、許可・拒否の両方を試す。

```text
for role in [engineer, tech_manager, rnd, ip, legal, executive, sysadmin, viewer]:
  for module in [M01..M25]:
    for op in [R, W, A, X]:
      期待どおり 200 / 403 / 404 が返ること
```

### 1.3 特別な制御

| # | 条件 | 期待 |
|---|---|---|
| B-1 | 起案者が自分の案件を承認 | 422 `WORKFLOW_SELF_APPROVAL_FORBIDDEN` |
| B-2 | 現場導入の遷移を安全品質環境ロール以外が実行 | 403 |
| B-3 | エクスポート権限のない者が C3 をエクスポート | 403 |
| B-4 | エクスポートした結果に透かし・注記がある | 含まれる |

## 2. Provenance テスト

| # | 条件 | 期待 |
|---|---|---|
| C-1 | 任意のAI実行（要約・分類・分解・審査・回答） | `ai_citations` が1件以上作成される |
| C-2 | 根拠が得られない入力でAI実行 | `ai_runs.status = 'invalid'`。画面に結果を表示しない |
| C-3 | `ai_citations.quoted_text` | 原文に**完全一致で存在する**（AI生成でないことの検証） |
| C-4 | `ai_runs.model` / `prompt_version` | 記録されている |
| C-5 | 受入検証クエリ | 根拠なしの `succeeded` が 0 件 |
| C-6 | 画面から根拠原文へ到達 | 2クリック以内 |

```sql
-- C-5 の検証
SELECT count(*) AS violations FROM ai_runs r
WHERE r.status = 'succeeded'
  AND NOT EXISTS (SELECT 1 FROM ai_citations c WHERE c.ai_run_id = r.id);
-- 期待: 0
```

```sql
-- C-3 の検証（例：特許の場合）
SELECT c.id FROM ai_citations c
JOIN patent_claims pc ON pc.id = c.source_id
WHERE c.source_type = 'patent'
  AND position(c.quoted_text in pc.text) = 0;
-- 期待: 0行（引用文が原文に存在すること）
```

## 5. 検索品質テスト

| 項目 | 方法 | 基準 |
|---|---|---|
| 正解セット | 代表50クエリ × 正解文献 | 技術・知財部門が作成 |
| Recall@20 | 正解のうち上位20件に入る割合 | ⚠️ 要決定 |
| Precision@10 | 上位10件の適合率 | ⚠️ 要決定 |
| MRR | 最初の正解の順位の逆数の平均 | ⚠️ 要決定 |
| 比較 | 字句のみ / 意味のみ / ハイブリッド | ハイブリッドが最良であること |
| 回帰 | 埋め込みモデル・重み変更時に再測定 | 悪化しないこと |

**MUST**: この測定を Phase 1 の完了条件とする（[ADR-0003](../20-architecture/adr/ADR-0003-japanese-search.md)）。

## 6. 非同期ジョブテスト

| # | 条件 | 期待 |
|---|---|---|
| F-1 | ジョブ起票 | 202 と `run_id` を返す |
| F-2 | 同一 `Idempotency-Key` で二重起票 | 同じ `run_id` を返す。二重実行しない |
| F-3 | 実行中に中止 | `cancelled`。部分結果が保存される |
| F-4 | 一時的な失敗 | 規定回数まで再試行される |
| F-5 | 再試行上限超過 | DLQ へ。`dq_issues` に起票される |
| F-6 | 権限が実行中に剥奪された | 次ステップで拒否される（起票時の権限を引きずらない） |
| F-7 | トークン上限超過 | 停止しアラート |

## 7. AI 回帰テスト（プロンプト変更時）

| 対象 | 方法 |
|---|---|
| Claim 分解 | 代表10件の請求項について、構成要件数と主要要件の抽出を確認 |
| 分類 | 代表50件の工種分類の一致率 |
| 模擬審査 | 代表5件について、リスク区分と人間確認事項が出力されること |
| RAG 回答 | 「資料にない質問」に対し「分かりません」と答えること |
| 指示注入 | 利用者入力に指示文を混ぜても従わないこと |

**MUST**: プロンプトまたはモデルを変更する PR では、本節を必ず実行する。

## 9. セキュリティテスト

| 項目 | 内容 |
|---|---|
| 認証 | Access を経由しない直接アクセスが拒否されること。JWT 改ざんの検出 |
| 認可 | §1 の全項目 |
| 入力 | SQLインジェクション、XSS、パストラバーサル |
| 秘密 | ログ・エラー・レスポンスにシークレットが出ないこと |
| レート制限 | 超過時に 429 |
| 依存 | critical / high の脆弱性ゼロ |
| 擬似認証 | 本番ビルドに含まれていないこと |
| R2 | 署名なしURLでオブジェクトへ到達できないこと |
