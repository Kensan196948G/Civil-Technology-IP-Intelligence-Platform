# 🧪 テスト計画

## 1. 方針

| 原則 | 内容 |
|---|---|
| 未検証で完了としない | テスト・レビューを経ないものを完了扱いにしない |
| 受入条件に紐づける | 各テストは要件ID（`FR-*` / `NFR-*` / `UC-*`）に対応させる |
| 権限を必ず試す | 「できること」だけでなく「できないこと」を試す |
| 根拠を必ず試す | AI実行に `ai_citations` が伴うことを機械的に検証する |
| フレーキーを放置しない | 不安定なテストは無効化せず原因を除去する |

## 2. テストレベル

| レベル | 対象 | 実行 | 目標 |
|---|---|---|---|
| 単体 | `packages/core` のロジック | PR ごと | 分岐網羅。⚠️ 目標値は要決定 |
| 結合 | API + DB（Neon ブランチ） | PR ごと | 主要APIを網羅 |
| E2E | 主要ユースケース（UC-01〜14） | PR ごと（主要導線）／夜間（全件） | 全 UC を網羅 |
| 権限 | 権限マトリクスの組合せ | PR ごと | 全ロール × 全モジュール |
| 性能 | NFR-P-* | フェーズ末 | 目標値との比較 |
| セキュリティ | NFR-S-* | フェーズ末 + 依存監査は毎PR | critical/high ゼロ |
| 受入 | 受入条件 A-01〜07 | フェーズ末 | 全項目合格 |
| 復旧 | バックアップ・リストア | 半期 | RTO 実測 |

## 3. 重点テスト領域

本システム固有のリスクが高い領域。ここは通常より厚くテストする。

| 領域 | 理由 | テスト内容 |
|---|---|---|
| **権限・機密区分** | 未公開発明の漏えいは致命的 | C3/C4 が非参加者の検索結果・件数・ファセットに出ないこと |
| **Provenance** | 設計上の絶対条件 | 全AI実行パスで `ai_citations` が作られること。0件時に `invalid` になること |
| **ワークフロー不変条件** | AIが決めない仕組みの担保 | AIステップ直後に人の確認が必ず入ること。自己承認が拒否されること |
| **注記の除去不可** | 類似率の誤用防止 | 類似度・スコアの表示に注記が必ず含まれること |
| **日本語検索** | 主機能 | 代表クエリでの再現率・適合率（[検索設計 §8](../30-design/06-search-and-rag-design.md)） |
| **非同期ジョブ** | 実行時間制約 | 失敗・再試行・中断・DLQ の挙動 |
| **マイグレーション** | 本番データ | 適用とロールバックの両方 |

## 4. テストデータ

| 環境 | データ |
|---|---|
| 単体 | インメモリの合成データ |
| 結合 | Neon ブランチ + シード |
| E2E | Neon ブランチ + シード（各ロールの利用者を用意） |
| 性能 | 大量の合成データ（⚠️ 件数は要決定） |

**MUST**: 実在の未公開情報をテストデータに使わない。

## 5. 実施スケジュール

| タイミング | 実施内容 |
|---|---|
| PR ごと | 単体・結合・権限・Provenance・主要E2E・依存監査・秘密スキャン |
| 夜間 | E2E 全件・データ品質チェック |
| フェーズ末 | 性能・セキュリティ・受入・復旧訓練 |
| リリース前 | 回帰テスト・スモークテスト手順の確認 |
| 半期 | 復旧訓練・権限棚卸し |

## 6. 合否基準

| 項目 | 基準 |
|---|---|
| 必須チェック | すべて成功 |
| 重大度 Critical / High の不具合 | ゼロ |
| Medium | 原則修正。残す場合は理由と対応予定を記録 |
| 受入条件 | A-01〜A-07 すべて合格 |
| 性能 | NFR-P-* の目標値を満たす（目標値は事前に確定させる） |
| 脆弱性 | critical / high ゼロ |

## 7. 不具合管理

```text
検出 → Issue 起票（再現手順・期待・実際・重大度・影響範囲）
   → 原因分析 → 修正 → テスト追加 → 検証 → クローズ
```

**同一原因の修正が3回失敗した場合**、修正の反復を止め、
設計上の問題として扱い、影響と代替案を整理して判断を仰ぐ。
