# 🔒 セキュリティ要件

## 1. 脅威と対策

| 脅威 | 影響 | 対策 |
|---|---|---|
| 未公開発明の外部流出 | **新規性喪失。権利化不能** | C3/C4 の行レベル制御、エクスポート制限、AI送信ポリシー、監査ログ |
| 権限のない社内利用者の閲覧 | 情報の目的外利用 | RBAC + プロジェクト権限。C3/C4 は 404 で秘匿 |
| 認証の回避 | 全情報の露出 | Access + アプリでの JWT 検証（二重） |
| AI経由の情報流出 | 機密が外部モデルへ | 送信前の分類判定、C4 は既定で送信しない、判定を記録 |
| プロンプトインジェクション | 意図しない出力・情報の引き出し | 利用者入力をデータとして区切る。出力をスキーマ検証 |
| 外部データの再配布違反 | 契約違反 | 出典保持、エクスポート時の出典表記、件数上限 |
| シークレット漏えい | 基盤の乗っ取り | Secrets 管理、秘密スキャン、ローテーション |
| 監査ログの改ざん | 説明責任の喪失 | 追記専用。DB権限で UPDATE/DELETE を剥奪 |
| 依存の脆弱性 | 任意コード実行等 | 継続監査。critical/high をゼロに保つ |
| 大量ダウンロード | 情報の持ち出し | 件数上限、レート制限、監査ログ、異常検知 |

## 2. 認証・認可

| 要件 | 実装 |
|---|---|
| SSO | Cloudflare Access + IdP（⚠️ IdP は要決定） |
| MFA | Access ポリシーで必須化 |
| JWT 検証 | 署名・`aud`・`iss`・有効期限を毎回検証。ミドルウェアで一元化 |
| セッション | アイドルタイムアウト（⚠️ 時間は要決定） |
| 再認証 | 管理者操作（権限付与・削除）で要求 |
| 内部呼び出し | Service Binding + 内部トークン |
| 擬似認証 | 開発環境のみ。本番ビルドに含めない（CI で検証） |

## 3. データ保護

| 区分 | 保護 |
|---|---|
| 通信 | TLS 1.2 以上。HSTS |
| 保存 | Neon / R2 の保存時暗号化 |
| バックアップ | 暗号化して R2 へ。アクセス権を限定 |
| オブジェクト | 公開バケットにしない。署名付きURL（有効期限つき）のみ |
| 下位環境 | 本番データをそのまま持ち込まない。C3/C4 は持ち込み禁止 |
| ログ | 機密本文・シークレット・個人情報を出力しない |

## 4. AI 固有のセキュリティ

| 要件 | 実装 |
|---|---|
| 送信範囲の制御 | 機密区分で判定。C4 は既定で送信しない。判定を `ai_policy_checks` に記録 |
| 入力の区切り | 利用者入力を明示的にデータとして囲む。指示として解釈させない |
| 出力の検証 | Zod で構造検証。検証を通らない出力を保存しない |
| 越境の防止 | 出力スキーマに侵害判定・法的判断のフィールドを持たせない |
| 引用の真正性 | 引用文は原文から機械的に切り出す。生成させない |
| コスト保護 | ジョブ単位・月次のトークン上限 |
| プロバイダ | 学習への利用可否・保持期間を確認する（⚠️ 契約条件を Phase 0 で確認） |

## 5. 監査

| 記録対象 | 内容 |
|---|---|
| ログイン | 成功・失敗 |
| 検索 | クエリ・条件・件数 |
| 閲覧 | 対象種別・ID・機密区分 |
| AI利用 | 実行種別・対象・モデル・トークン量 |
| Export / Download | 対象・形式・件数 |
| 更新・削除 | 対象・変更前後（機密本文は含めない） |
| 承認 | 承認者・決定・対象版 |
| 権限変更 | 付与・剥奪・実施者 |
| **拒否された操作** | 権限不足での拒否も記録する |

| 要件 | 実装 |
|---|---|
| 改変不可 | 追記専用。`ctiip_app` から UPDATE/DELETE を剥奪 |
| 保持期間 | ⚠️ 要決定（法定・社内規程と整合） |
| 検索 | 期間・利用者・操作種別・対象で検索できる |
| 出力 | 監査担当が改変不可の形式で出力できる |

## 6. 運用上の統制

| 項目 | 内容 |
|---|---|
| 権限棚卸し | 半期ごと。異動・退職時は即時 |
| 最小権限 | 既定は最小。必要に応じて個別付与し、期限を設ける |
| 職務分離 | 開発者が本番データへ直接アクセスしない。運用操作は監査対象 |
| 変更管理 | 高リスク変更は専用PR + 🔒 承認 |
| インシデント | [../70-operations/04-incident-response.md](../70-operations/04-incident-response.md) |

## 7. 法令・規程との整合

| 事項 | 対応 |
|---|---|
| 職務発明規程 | 発明者・持分・届出日時を保持。⚠️ 規程改定と整合させる |
| 個人情報 | 発明者名・研究者名の取扱いを規程に沿って行う |
| 外部データの利用条件 | 出典保持、再配布制限の遵守 |
| 資格業務との境界 | 社外への鑑定・法的判断の提供を行わない。システム上で担保 |
| 監査対応 | ISO / J-SOX 等の要求に応じた証跡を提供できること（⚠️ 要求事項は要確認） |

## 8. 実装時の必須確認

| # | 確認 |
|---|---|
| 1 | 権限条件が SQL に含まれているか（後段フィルタでないか） |
| 2 | C3/C4 の非参加者に 404 を返しているか |
| 3 | 総件数・ファセットから機密が漏れていないか |
| 4 | 監査ログを記録しているか（拒否も含む） |
| 5 | シークレットをログ・レスポンスに出していないか |
| 6 | AI送信前に分類判定をしているか |
| 7 | エクスポートに透かし・注記・出典があるか |
| 8 | 擬似認証が本番ビルドに含まれていないか |
